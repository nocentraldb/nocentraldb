# 2026-11-26 · NOC-541 · The Rust SDK's error texts are generated into shard files by a hash of their ids, and the texts gate fails on a generated module over the limit for a file

- Decided by: coding agent, NOC-541
- Why: `crates/nocentraldb/src/texts/error.rs` held all of the SDK's error texts and reached 699 of the 700 lines `repo:file-size` allows, so no new error text fitted (#500 reused one instead). `scripts/texts.mjs` now writes the kinds in `SHARDS` (today `error: 4`) as a folder, `texts/error/mod.rs`, which re-exports `shard_0.rs` to `shard_3.rs`, so code still names `texts::error::NAME`. A text's shard is the first four bytes of a SHA-256 of its id, modulo the count, so a new text moves no other and two pull requests' new texts rarely meet in one file; every shard is written even when empty, so the files do not come and go. `scripts/texts-size.mjs` checks every generated text module (the SDK's, the command line's, the TypeScript SDK's and the core's) against the limit in `factory/CONFIG.md` and names the fix: raise the kind's count in `SHARDS`, or add a concern to the core's `CONCERNS`. Raising the count moves most texts once, in one generated commit.
- Instead of: one file per group of texts by name prefix, as the core's `CONCERNS` are, which needs a list kept by hand and whose groups grow unevenly; a shard count derived from the number of texts, which would move every text whenever the count changes; or a higher limit for generated files, which changes `repo:file-size` and goes to the owner.
- Topics: texts, gates, sdk-rust
