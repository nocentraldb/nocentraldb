# 2026-11-09 · NOC-61 · The README's code examples follow RFC 0009, and the schema example leaves out computed fields and views

- Decided by: Carsten (owner), 2026-11-09, accepting pm's proposals for the README examples after deciding RFC 0009 (S1 to S18)
- Why: the examples must use only names an RFC defines (NOC-61), and RFC 0009 now defines the SDK's names. So they open with `nc.open({ model, lock })`, the relay optional; create a space with `db.spaces.create()`, without a name, since a name is content (S11); write with `project.write((tx) => { tx.create(...); tx.update(...); })`, one call one change; query through a declared index, `db.find(model.tasks.indexes.byStatusPriority.equal("open").take(50))` and `.after(page.cursor)`; subscribe with `db.subscribe`; invite with `db.invitation()` on the joining member and `nc.invitation(text)` on the admin, whose calls return a notice `{ code, text }`; and read the sync state with `db.sync.current()`. The schema example drops `computed` and `views` (`nc.reach`, `nc.view`), which RFC 0005 reserves but does not design. The examples link RFC 0009, and `scripts/readme.test.mjs` checks every identifier in them against the RFCs' code.
- Instead of: the first draft's sketches from RFC 0003 and RFC 0001 (`nc.open({ model })`, `db.spaces.create({ name })`, `db.find` on a view) and leaving out the write step, which no RFC named before RFC 0009.
