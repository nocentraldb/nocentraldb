# 2026-11-12 · NOC-272 · The `connections` table holds one item per connection and one per subscription, held to one contract with the in-memory store

- Decided by: coding agent (NOC-272), following RFC 0007, "Tables and keys"
- Why: RFC 0007 gives `connections` a partition key of connection id, a sort key of space id, a TTL and two indexes. The partition key is the API Gateway connection id as text. The sort key is `#` for the connection's own item and the space id in lowercase hex for a subscription. The connection item holds the step of its opening, with the nonce while it waits for `auth` and the member once it acts as one. The member attribute keys the sparse index `by_member`. A subscription holds its space, which keys the index `by_space`, and its member as `subscriber`, so it never lists in `by_member`. `ttl` is in seconds, as DynamoDB reads it, and `expires_at` in milliseconds. An expired record reads as gone in every store, before the TTL deletes it. One contract, `ncdb_relay_lambda::contract`, holds the DynamoDB store and the in-memory store to the same rules, and the DynamoDB store passes it against the AWS Emulator. The indexes are read eventually consistent: a subscription made a moment ago may miss one live delivery, which RFC 0007's best-effort delivery allows.
- Instead of: one item per connection with its subscriptions in a list, which a space's subscribers could not be found by; or the member on subscription items too, which would make `added` go to a connection once per subscription.
