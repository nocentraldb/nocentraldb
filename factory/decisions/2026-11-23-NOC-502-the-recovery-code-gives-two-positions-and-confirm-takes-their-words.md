# 2026-11-23 · NOC-502 · `RecoveryCode::challenge()` gives two positions picked once per code object, and `confirm(answers)` takes the words typed back at them, in that order

- Decided by: coding agent (NOC-502); the names go to the owner in the PR
- Why: `challenge()` gives two different positions from 1 to 12, counted from 1 and in order (`[usize; 2]` in Rust, `readonly [number, number]` in TypeScript). The core picks them from the platform's secure generator when it hands out the code, so they stay the same for one object, which a screen that renders twice needs, and the next `recovery_code()` picks new ones; one core picks them for both SDKs. `confirm(answers)` takes the two words in the order of `challenge()` (`[&str; 2]`, `readonly [string, string]`), so the app passes back only what the person typed. In Rust `confirm` borrows the code instead of consuming it, so the same object takes a corrected answer after a typo. Through the bridge, `account.recoveryCode` answers `{"words", "challenge"}` and `account.confirmRecoveryCode` takes `{"answers": [{"position", "word"}; 2]}`, refusing anything but two words at two different positions from 1 to 12. The TypeScript `RecoveryCode` stays an exported type, now `{ words(): readonly string[]; challenge(): readonly [number, number]; confirm(answers: readonly [string, string]): Promise<void> }`, whose `toString()`, `toJSON()` and Node's inspect give `"RecoveryCode(redacted)"`.
- Instead of: positions the app chooses, which would let an app ask for the same two words every time; answers that carry their positions in the public API; new positions on every `challenge()` call; `confirm(self)` consuming the code even when a word is wrong.
