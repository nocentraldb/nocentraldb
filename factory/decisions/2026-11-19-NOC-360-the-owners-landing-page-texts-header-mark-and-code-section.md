# 2026-11-19 · NOC-360 · The owner's landing-page texts, the header mark and the code section

- Decided by: Carsten, 2026-11-19, in chat with pm (batches 1 and 2 of his review of #383, relayed by pm with pm's grammar and glossary fixes, each of which the owner can overrule)
- Why: the landing page leads with what a visitor gets, in words a visitor knows. The hero reads "Reads like local files, syncs like shared docs", and its lead (also the page's description) says the database puts the data next to the people and agents who use it while the server only ever sees encrypted data. The scenario is "Two people, one of them travelling, and an agent work on the same task list", in four steps told from the traveller: "Everyone has the full task list", "A change travels encrypted", "The traveller goes offline", "The traveller reconnects". The header shows the yellow `ncdb` mark beside the wordmark, and only the mark on a phone; the link keeps the name NoCentralDB. The code section is "Get started": seven steps (Install, Model, Open, Share, Write, Read, Subscribe), each in TypeScript and in Rust behind one switch that the page remembers per viewer, its code highlighted in the brand's dark palette at 4.5:1 or more. The install lines follow `release-notes/index.json` when the site is built: a release installs plainly, a beta by npm's dist-tag `beta` and the crate's exact prerelease version, and before the first beta npm's `alpha` and the crate from the newest alpha tag, since crates.io holds only a placeholder. The section says "The SDK handles all the encryption. Your code never touches a key.", with a footnote that the app passes on one secret, the account's recovery code (option B). The docs' header shows the mark too, and the drawings' alt texts tell the scenario in the new words. The demo invites the visitor to watch the Network tab: adding or changing a task sends no request, and a second window of the page follows because both share one database in this browser. It lists the newest task first, through a model and lock of its own that add a creation time and an index on it, descending, as an additive successor of the first lock, so a visitor's stored database still opens; tasks from before have no creation time and come last, by title. The docs say what work orders are, clean-up jobs that one member does and another checks, compaction the main one, that 0.1 runs none, and that erasing a person works through its own path; a page "How NoCentralDB works" (sidebar "Overview", the owner's choice over "Core concepts") explains the core concepts on one running example, a project app of projects, tasks and people, with the decision and its consequence per concept (a space per project and one for the people, one model for every space, a link inside a space against a reference across spaces, personal fields and erasure, roles per space), TypeScript and Rust that type-check and compile, what 0.1 cannot do yet said on the page, and three RFC 0001 diagrams copied into the brand's dark palette. In the pinned scenario each step holds a screen of scroll with a snap point (option b), and a gesture lock moves it by one step per wheel or trackpad gesture, natively past its first and last step. pm's fixes: "everyone" for "members" in the lead, since a visitor does not know the term; "person" and "traveller" for "user", which the glossary avoids; "reading needs no network", since syncing does; "carry on from the last state they know" for "don't care" and "are not aware"; British spelling, as the site's prose uses it.
- Instead of: the headline "A database that reads like a local file and syncs like a shared doc", the lead "Each person and each agent reads and writes a full copy on their own machine…", the scenario "One task list on a train, in a home office and with an agent" with its four steps of 2026-11-12, a header with the wordmark alone, and a code section "Five calls in the SDK" in TypeScript only, in ink and muted, with a separate install line and `cargo add nocentraldb`; a scenario whose four steps shared one screen of scroll, which a trackpad flick ran through; the demo's alphabetical order through the model of apps/tasks-ts; and, for the lock, the Lenis library, which takes over the whole page's scrolling and snaps only after scrolling has settled.
