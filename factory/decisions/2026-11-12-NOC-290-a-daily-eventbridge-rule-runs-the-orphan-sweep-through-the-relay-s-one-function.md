# 2026-11-12 · NOC-290 · A daily EventBridge rule runs the orphan sweep through the relay's one function

- Decided by: coding agent (NOC-290)
- Why: RFC 0007 promises a daily sweep of the frames an append wrote to S3 before its transaction failed. The function now reads each invocation's event as JSON (`ncdb_relay_lambda::invocation`). An event that is exactly `{"ncdb-relay":"sweep-orphans"}` runs `AwsStore::sweep_orphans` with a cutoff a day back, so it never deletes the frame of an append in flight. An event with `requestContext` goes to the WebSocket handler as before. Anything else is refused. A member's message is only ever an event's `body`, so no WebSocket event can reach the sweep, even when its text is the sweep's input. An EventBridge rule in the stack invokes the function at 03:17 UTC daily with that input and retries twice. The rule's resource permission allows only that rule (`SourceArn`), and needs no role. A failed sweep fails its invocation, so the function's error alarm mails the owner; its log line keeps only the cutoff, the count or that it failed. The rule's test reads the input from the Rust source, so the two cannot drift apart. CloudFormation's execution policy gains the rule's handler actions, limited to `rule/NoCentralDbRelay-*`.
- Instead of: a second function for the sweep, which doubles the package, the role and the alarms for one call a day; EventBridge Scheduler, which needs its own IAM role to invoke the function where a rule needs only a resource permission; or reading EventBridge's own "Scheduled Event" shape, which any rule in the account could send.
