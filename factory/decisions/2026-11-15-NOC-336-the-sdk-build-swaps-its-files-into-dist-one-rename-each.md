# 2026-11-15 · NOC-336 · The SDK's build swaps its files into dist/ one rename each, and binaries are renamed into place

- Decided by: coding agent (NOC-336, on pm's choice of the smaller change that keeps CI's behaviour)
- Why: `packages/sdk/build.mjs` emptied `dist/` before it built, and each sdk-browser e2e file runs the build in its `before`. When the files run in parallel, a file whose build finished first loads its page while another file's build has emptied `dist/`: the page's module is a 404, `window.ready` never comes, and the load waits out its 30 s. A forced race, page loads while the build runs again and again, failed 40 of 40 loads, and passed 40 of 40 without the build. The build now writes into `target/sdk-dist/build-<pid>`, moves each file into `dist/` with a rename, which replaces a file at once, and removes the files it no longer builds; with it, the forced race passes 300 of 300 loads beside 24 builds. The relay server and the Rust peer the e2e files copy into `target/sdk-browser/` are copied beside and renamed over, since a copy onto a binary another file runs fails with `ETXTBSY`. CI builds once and runs the files prebuilt, as before.
- Instead of: a moon task that builds once before the files, which leaves a direct `node --test 'scripts/sdk-browser/*.test.mjs'`, the run that failed, as racy as before; `--test-concurrency=1`, which makes every local run three times slower; swapping the whole directory with two renames, which leaves a moment without `dist/`; or a longer page-load timeout, which the ticket rules out.
