# 2026-11-13 · NOC-272 · The deploy role lives in a private repository, and the owner approves every deployed change

- Decided by: Carsten, 2026-11-13, through pm on #299
- Why: The OIDC provider, the deploy role and CDK's bootstrap with the narrowed execution policies move to the private repository `nocentraldb/aws-deploy`; this repository keeps no role setup. Deploying from this repository through that role stays: `relay-deploy.yml` keeps its build and deploy jobs on `main` in `aws-prod`. Every change to code that is deployed to AWS needs the owner's explicit approval before it merges, and agents and pm never merge such a change themselves. `.github/CODEOWNERS` makes `@cabcookie` the only owner of exactly the workflow's trigger paths and of itself; `scripts/relay-deploy-workflow.test.mjs` keeps the two lists equal, and the trigger paths equal to every workspace crate the function links, which added `crates/ncdb-plugin`. The runbook asks for a ruleset on `main` (a pull request, one approval, review from Code Owners, stale approvals dismissed) and for "Required reviewers: cabcookie" on `aws-prod`, so every deploy also waits for the owner. This supersedes the narrowed execution role's place in this repository (its policies and test move to `nocentraldb/aws-deploy` unchanged).
- Instead of: keeping the role setup in the public runbook, which the owner chose to keep private; relying on the agents' rules alone, with no CODEOWNERS or environment reviewer; or listing the owned paths by hand without a test, which drifts the first time the function links a new crate.
