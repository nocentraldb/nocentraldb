# 2026-11-09 · NOC-67 · Rights and verdicts in `resolve` where RFC 0008 leaves a detail open

- Decided by: coding agent (NOC-67)
- Why: each rule depends only on the set of control changes, so every holder applies it the same way. (1) A genesis is valid only when its first generation is the id "Generation ids" derives with no previous generations, and its certificate is a device's or an agent's that its account signed: "How the relay and members recognise it" lists the other rules, and "Generation ids" says every member recomputes the id. (2) A member's own set role needs the role it sets, so lowering its own role is allowed and raising it is not; its own remove needs reader. Every other membership entry needs admin. (3) Entry types 2 to 6 need the right RFC 0008's table names (admin, admin, writer, writer, reader); their own rules wait for the tickets that read their bodies, so here they are judged on the right alone and change no state. (4) A change that an accepted revocation excludes is reported as excluded by that revocation, before a missing right, which the exclusion explains. (5) An accepted grant that a revocation it did not see caps below its role is "lost"; the genesis's grant counts too. (6) Only a holder's dependencies count: a missing one is a gap, which `Resolved::gaps` lists for every decoded body, and a change whose only path to the genesis runs through a gap has no genesis in its causal past and is not valid when written.
- Instead of: reporting a missing right before an exclusion, which hides the revocation that caused it; or treating the other entry types as not understood, which would let a revoked member's acknowledgements and rotations escape exclusion.
- Topics: membership, rfc-0008, convergence
