# 2026-11-10 · NOC-190 · The space status reads its fields from the copy and the sync state, and leaves out what is not built

- Decided by: pm, on the coding agent's recommendations (NOC-190, Q1, Q3 to Q5); the names are the owner's (NOC-193)
- Why: RFC 0009's `space.status` lists twelve values. Ten have a source today. `role` is the role the copy folded, or `None` once the relay stopped the space, as `spaces().list()` does. `gaps`, `lost_grants` and `exposed` come from the membership the copy resolved, and `exposed` is the exposure of the current generation. `waiting_for_key` is true while the member is a member but holds no key for the current generation. `parked` and `rejected` come from counts the core's log keeps per reason as states are set (`Log::state_counts`, `View::state_counts`), so neither `current()` nor a subscription decodes the log. `parked` sums changes and operations under one reason each, and the RFC's reasons never overlap between the two. `refused` lists this member's own refused changes in local order, read from the log in memory (`Log::refused_by`), each code through `wire::mapped_code` (NOC-188). `initial_sync_complete` and `behind` come from the relay's head, which the sync state keeps per space in memory like the cursors. The initial sync is complete once the cursor reached the head in this relay epoch since the database opened, `behind` is the head minus the cursor, and both are `false` and 0 without a relay. `subscribe()` follows the status the way `db.sync().subscribe()` follows the sync status, by one shared stream over a read of the database.
- Instead of: fields that always read empty for what is not built (`newest_model`, the "another model" reason, `shreds_waiting`), which would claim nothing waits (GENESIS principle 4); `SpaceStatus` is `#[non_exhaustive]`, so each comes when it is built: key 64 and shred stability are their own tickets, equivocations a second PR of NOC-190. Also instead of a scan of the log per read, which a subscription would repeat after every change.
- What this does not do: `initial_sync_complete` and `behind` reset when the database reopens, since the SDK forgets the relay positions then (NOC-90) and pulls again from 0.
