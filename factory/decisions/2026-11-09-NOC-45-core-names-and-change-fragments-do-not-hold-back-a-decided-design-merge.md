# 2026-11-09 · NOC-45 · Core names and change fragments do not hold back a decided-design merge; pm merges a beta's notes

- Decided by: owner (Carsten, 2026-11-09, on NOC-45), as pm recommended (A and A)
- Why: GENESIS.md reserves "public API names" and "release notes" for the owner, and almost every implementation PR adds core types and a change fragment. Public API names are decided in the RFC: a PR that only implements an accepted RFC may be merged by pm, whatever `pub` names of `ncdb-core` it adds or changes, because those are building blocks below the SDK and cheap to change before a release. An SDK name that no RFC names still goes to the owner. The release notes that matter are the curated notes of a stable release, which the owner curates. An agent curates a beta's notes, and pm merges that pull request without the owner, ticking the new authorship box "Agent, beta release notes" (the owner, asked by pm, the same day). An alpha's notes are generated from the fragments. So a change fragment is not a release note. `factory/roles/pm.md`, `factory/CONFIG.md`, `.github/AI_POLICY.md`, the pull request template and `docs/release-management.md` carry these rules.
- Instead of: counting every `pub` core name as a public API name, or every fragment as a release note, which would leave nearly every implementation PR with the owner and make the decided-design exception do almost nothing; or counting core names only from the first release on; or the owner approving every beta's notes, as the runbook said before.
