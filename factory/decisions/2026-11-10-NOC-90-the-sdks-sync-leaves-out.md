# 2026-11-10 · NOC-90 · What the Rust SDK's sync leaves out, and the Rust names it uses until the owner confirms them

- Decided by: coding agent (NOC-90), as a safe subset; pm told on 2026-11-10
- Why: the ticket asks for push, pull, subscribe, reconnect, the epoch and the counts of the sync status. Built: `OpenOptions::relay(url)`, `Db::sync()` returning `SyncReport`, whose `current()` returns `SyncStatus { connection, unconfirmed, refused, epoch_changed, error }` with `Connection::{Connected, Connecting, Offline, Paused, None}`, RFC 0009's table in Rust case. RFC 0009 names `db.sync.current` but no Rust type, and `Sync` would shadow std's marker trait, so these three names wait for the owner's word, which pm asks for. Left out: TLS, so `Db::open` refuses a relay URL that is not `ws://` with `InvalidValue` rather than retrying a connection that can never open; `db.sync().subscribe()`, `pause()`, `resume()`, `is_confirmed()`, `confirmed()` and the per-space `status`; a handle to write into a space the member was added to (its changes are pulled and folded, but `spaces().get` is not built); a large change's download link. A pulled change wakes every subscription of its space, since the SDK does not decrypt to learn its collections.
- Instead of: guessing more public names the owner has not seen, or retrying a `wss://` relay forever as `offline`.
