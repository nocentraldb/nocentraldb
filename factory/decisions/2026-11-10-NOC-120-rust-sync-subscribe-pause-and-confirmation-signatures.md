# 2026-11-10 · NOC-120 · The Rust signatures of `sync().subscribe`, `pause`, `resume`, `is_confirmed` and `confirmed`

- Decided by: pm, on the coding agent's recommendation (NOC-120, Q1 to Q4)
- Why: RFC 0009 names these calls in Rust only as "every name above in snake case", and fixes no signature. They add no public type name and follow the SDK's existing patterns. `SyncReport::subscribe(&self) -> impl Stream<Item = SyncStatus> + Unpin` yields the status at once and again whenever it differs from the last one it yielded, like `Db::subscribe`; dropping it stops it. `async fn pause(&self)` and `async fn resume(&self)` return `()`, since the Rust SDK has no `closed` error. A pause reports `Connection::Paused` from the moment it returns; from then on, the SDK sends the relay nothing and records nothing it answers, until `resume` connects again at once with the backoff started over. A pause lasts while the `Db` is open, and on a database without a relay both calls do nothing. `fn is_confirmed(&self, change: ChangeId) -> bool` says whether the log holds a relay position for the change in the relay's current epoch, so it turns false again after an epoch change until the change is pushed again; a change the relay refused, or that the database does not hold, has no position. `async fn confirmed(&self, change: ChangeId)` resolves when `is_confirmed` turns true, and may never resolve (RFC 0009, S3).
- Instead of: a named stream type, or `confirmed` returning `Result` and failing on a refusal, which RFC 0009's "may never resolve" rules out.
- What this does not do: a pause is not kept across a reopen. To learn of every change of the status, `Inner` holds the list of followers (`sync::Notify`), the one change outside `sync/`.
