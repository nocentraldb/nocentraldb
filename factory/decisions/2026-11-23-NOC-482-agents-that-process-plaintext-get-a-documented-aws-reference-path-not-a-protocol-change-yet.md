# 2026-11-23 · NOC-482 · Agents that process plaintext get a documented AWS reference path, not a protocol change yet

- Decided by: Carsten, 2026-11-23, on NOC-482 ("NoCentralDB muss nicht alle Probleme lösen … Wir schlagen einen Weg vor, der mit AWS gut funktioniert und dokumentieren seine Grenzen", then "Klingt super. Mach es so" on pm's proposal)
- Why: NoCentralDB protects data end to end; once a person lets an agent read a space in the cloud, the remaining risks lie with the cloud and the app operator, not with NoCentralDB's protocol. One documented path that works well on AWS, with its limits stated plainly (GENESIS: say plainly what it does not do), serves apps now without NoCentralDB solving hosting for every provider. The path: the agent runs on an attested instance and holds its member key there; the model runs on Bedrock through Mantle, with `data_retention_mode: none` and only models without model-specific abuse retention; the relay endpoint is protected by the app's authorizer with a delegation token; the guide lists the public audits with the date they were checked and the observability defaults that could expose content. Other providers are invited as community "agent hosting guides" with the same sections. The word "adapter" is not used, because GENESIS already uses it for connecting a change stream to other systems.
- Instead of: an RFC "attested agent members" now, where the person's device verifies an attestation before it adds an agent or hands over a key. It stays on the roadmap; today the guide describes key release after attestation as an operator practice (a KMS key bound to the image measurements).
