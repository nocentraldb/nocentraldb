# 2026-11-23 · NOC-492 · The relay remembers each space's resolve in its process, up to 10,240 control changes over all spaces, and stores nothing new

- Decided by: coding agent (NOC-427; its bound: NOC-492)
- Why: each push of a control change and each put of person-key records read and resolved every control change of the space from scratch. A memory per process, the control changes read so far and a `membership::Resolver`, makes a warm instance read and judge only what is new, and answers stay a function of the log: a new relay epoch, or a log that no longer holds the last entry read at its position, makes it read the space again. Since the resolver keeps causal pasts as ranges of node numbers (NOC-442), a remembered space holds about 7.7 KiB per control change, linear in its persons (75 MiB at 10,000), and a cold request on it allocates at most about 10.4 KiB per control change at once (104 MiB at 10,000), measured natively on Linux. So the memory is weighed by control changes, not their square: at most 16 spaces and 10,240 control changes over all of them, least recently used forgotten first, which with one request's work on a space it would keep takes about 185 MiB of a 256 MB Lambda.
- Instead of: a persisted snapshot of the resolved state in a new DynamoDB item (a new stored format to version and keep equal to the log, which the owner would have to decide), no memory and a larger Lambda, or keeping the square of the control changes as the weight (a bound of about 1,200 control changes, far below what fits since NOC-442)
