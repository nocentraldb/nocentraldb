# 2026-11-20 · NOC-403 · pm merges tests and RFC-following fixes, and the deployed crates' tests need no owner review

- Decided by: Carsten, 2026-11-20, in chat with pm ("Option A")
- Why: the owner's review is the factory's bottleneck, and most PRs that waited for it decided nothing: tests of behaviour a decided RFC or GENESIS states, and fixes that make code do what decided RFC text already says. The first exception of `.github/AI_POLICY.md` ("a decided design") now covers both kinds, with its limits unchanged: no departure from an RFC, no public name, format or runtime dependency the RFC does not name, no gate changed, nothing new decided. The owner keeps, even when a PR fits: key handling and cryptography, the wire and on-disk formats, public API names and types in the SDKs, erasure, any fix labelled security, gates, CI and release workflows, and `factory/`, `.github/`, GENESIS and the README. The `tests/` directories of the five crates the relay is deployed from leave `.github/CODEOWNERS` (a later line with no owner, since CODEOWNERS takes the last match and has no `!`), and `relay-deploy.yml` excludes them from both path filters (each `!` after the pattern that includes its crate); their `src/` stays owned, as NOC-272 decided, inline `#[cfg(test)]` modules included. pm hands the owner reviews in bundles, at most twice a day, each PR with the one point to check. `factory/CONFIG.md` and `factory/roles/pm.md` carry these rules.
- Instead of: the rule of 2026-10-31 (memory `owner-reviews-every-pr`) that every agent PR waits for the owner's tick except the four exceptions; and owning the deployed crates' test directories, which made every test-only change wait for the owner's GitHub review and start a deploy run.
