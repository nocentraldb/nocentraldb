# 2026-11-12 · NOC-175 · The browser syncs over its WebSocket and fetch(), with the session and loop natively in use

- Decided by: coding agent (NOC-175, sync slice, step 2), on the owner's answers to NOC-245 (A for each: CORS for any origin on the large-change URLs, any Origin on the relay, no SDK rule for `ws://` in a browser)
- Why: #245 put the session behind `Transport` and a clock of its own, so the browser needs only what differs there. `transport::browser` wraps `web_sys::WebSocket` with binary messages as ArrayBuffers, handed to the session through tokio's unbounded channel (its "sync" feature, already on), with RFC 0007's largest message as the limit, as natively. The loop runs through `wasm_bindgen_futures::spawn_local` on the event loop of the page or worker that opened the database: wasm32 has no threads to run a runtime of its own on. Large changes go through the global `fetch()`, which a window and a worker both have, with redirects refused and a download read as a stream that fails as soon as it is longer than the announced size, the native client's strictness where the browser allows it. The session signs the SDK's own copy of the relay-auth digest, which a native test pins equal to the relay's, because `ncdb-relay` bundles SQLite for native and does not build for wasm32; it becomes a dev-dependency. The relay server answers CORS on its own, since it has no bucket to configure.
- Instead of: a hand-written `select!` replacement to avoid tokio's "macros" feature, which would duplicate tokio's and the session already uses `select!`; reading the download with `arrayBuffer()`, which takes a body of any size before it can be checked; an SDK refusal of `ws://` in a browser, which the owner did not take (NOC-245, 3A): the browser refuses it on an `https://` page, and the database then stays offline; `web_sys::WorkerGlobalScope::fetch`, which a window lacks.
- What this does not do: the browser's tab ownership, `db.close()` in the browser, and the TypeScript SDK, which name the browser database publicly (NOC-176). The AWS backend's bucket CORS rule is written in RFC 0007 but built with that backend.
- Tests: `ncdb-relay-server/tests/cors.rs` (preflight and headers); `wasm_tests` in Node (a database with a relay opens and goes offline); `browser::tests::sync` in Chromium against the local relay, which the `sdk-keys` harness builds and starts (two databases share a space; a 300 KiB change through `fetch()` from another origin).
- Topics: sdk-rust, sync, wasm, browser, relay
