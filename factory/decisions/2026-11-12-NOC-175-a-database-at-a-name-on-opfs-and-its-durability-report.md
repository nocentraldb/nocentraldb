# 2026-11-12 · NOC-175 · A database at a name on OPFS, and the durability report that counts own changes without a relay position

- Decided by: coding agent (NOC-175, OPFS slice, part 1), confirmed by pm
- Why: RFC 0006 ("What the SDK reports") gives `unconfirmed` as the changes this member wrote that have no relay position yet, and `atRisk` as true while they exist and storage is not persistent. The crate-internal `Durability` counts, per space, this member's changes the relay neither confirmed nor refused plus the ones it refused, from the view's relay counts, since both exist only on this device; a peer's changes are not counted. It has no `oldest_unconfirmed_at`: the log keeps no time per change, and where that time comes from is NOC-231 question 5. In the browser, the keys follow the native keystore's rule: an open that finds no keys for a database whose file exists fails with `StorageFailed` and draws none, since new keys would open none of its spaces. Whether the file exists comes from the core's new `view::browser::exists`, read from the `opfs-sahpool` pool through `sqlite-wasm-rs`'s re-export of `VfsFilesManager`, so no dependency is added.
- Instead of: counting only the changes the relay neither confirmed nor refused, which would call a refused change safe although it exists nowhere else; drawing keys for an existing database without them, which would lose its spaces; adding `rsqlite-vfs` as a direct dependency of the core for the trait.
- Then, on the owner's NOC-231 (A for all five; Carsten, 2026-11-12): the log gains `written_at`, which the SDK sets with every change it writes and the report's `oldest_unconfirmed_at` reads; a database at a name opens on OPFS at `/<name>/nocentraldb.sqlite` in `.opfs-sahpool`, reserving two slots (the core's new `view::browser::reserve`); names are 1 to 64 characters of a-z, 0-9, `-` and `_`; a pool another tab holds fails with `StorageFailed`; the worker reads `persisted()` and the page asks. `Db::open` reaches it through a crate-internal `OpenOptions::browser(name)` on wasm32; the copy's storage is `Temporary` in memory, `Persistent` at a path, and from `persisted()` on OPFS.
- What this does not do: name `browser(name)` or `durability()` publicly (NOC-176); elect an owner tab with Web Locks; run the browser tests in Firefox and WebKit; date the changes a member wrote before the log kept the time.
- Topics: sdk-rust, wasm, browser, opfs, durability, keys
