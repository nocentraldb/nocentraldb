# 2026-11-10 · NOC-93 · The core resolves a reference against the member's copies, one map of spaces, and reuses the link's object check

- Decided by: coding agent (NOC-93)
- Why: RFC 0004 Amendment 4 leaves the core's shape open. `ncdb_core::reference` holds the type `Reference { collections }`, its value `[space id, object id]` (`reference::value`, `reference::target`), and `Reference::resolve(state, copies)`, which gives the winner and each conflict a `Status`: `Ok`, `NotAccessible` or `Missing`, the working names of RFC 0005's D20. `copies` is a `reference::Copies`: the member's copy of each space it holds, by space id, so "not accessible" is exactly "no copy of that space" (decision 20). Inside a held space, the target is checked as a link's is, and everything but the link's `Ok` (deleted, absent, a collection the field does not list) reads `Missing` (decision 18). A value that does not fit, and a cleared reference, name no target and read `Missing` (decision 17). The reference merges through `basic::Values::References`, beside the link's `ObjectIds`, so it shares basic values' code and their contract checks. `Reference::set` takes a target in any space, its own included (decision 19).
- Instead of: a resolver that asks the control state whether the member is a current member of the target's space, which decision 20 B describes and the owner did not choose; or a fourth, reference-only copy of the link's object check.
