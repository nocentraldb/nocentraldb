# 2026-11-23 · NOC-498 · Recovery may restore spaces through an opt-in space-key backup at the relay

- Decided by: Carsten, 2026-11-23, on NOC-498 ("Ich stimme der Empfehlung zu (in beiden Aspekten)"), at nexflow.it's request (their NEX-60)
- Why: today the recovery code restores the account, not its spaces; a space whose only member was a lost device stays unreadable for good (RFC 0010). For a person with a single device that loses their data, which GENESIS principle 3 ("Nothing is lost silently") argues against. A backup of the space keys at the relay, sealed under a key derived from the recovery code with a memory-hard derivation, lets the code alone restore those spaces while the relay stays blind. Because a leaked code then reads every backed-up space at once, the backup is opt-in per space and off by default, with a status that says a space is backed up, and it may be narrowed to spaces whose only member is one device. Timing: the RFC (a change to RFC 0010 and RFC 0007) is written in December 2026 so its design is decided before the February beta; the build follows after the beta, before nexflow.it's go-live in March 2027. Until then the single-device warning (NOC-494) and a second member cover the gap.
- Instead of: a backup for every space by default; keeping RFC 0010 as it is.
- Topics: accounts, recovery, relay, security
