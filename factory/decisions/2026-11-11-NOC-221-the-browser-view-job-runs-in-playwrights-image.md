# 2026-11-11 · NOC-221 · The browser jobs run their browsers in Playwright's image, without apt

- Decided by: coding agent (NOC-221), on pm's brief (the container image or a cache, a fast timeout and one retry)
- Why: `playwright install --with-deps` installs the browsers' system libraries with apt, and an outage of the runner's apt mirror and DNS failed the job before any test ran (#199). Playwright's image `mcr.microsoft.com/playwright` holds the browsers and their libraries at one Playwright version; the job pins it to the version package.json pins, by digest, and pulls it with a 4-minute timeout and one retry. The image has no Rust and no C compiler, so the harness and the native run are built on the runner, which needs nothing from apt, and kept in `target/browser-view`; the tests run in the image with `BROWSER_VIEW_PREBUILT=1` on the checkout and its node_modules. browser-storage.yml, which needs no build, runs its probe and its measured rows in the same image. The contract tests `scripts/browser-view-workflow.test.mjs` and `scripts/browser-storage-workflow.test.mjs`, with the shared checks in `scripts/lib/playwright-image-checks.mjs`, keep the image's version and package.json's in step.
- Instead of: running the whole job in the image, which needs Rust and a C compiler installed with apt again; caching apt's packages, which still needs the mirror on every cache miss and for `apt-get update`.
- What this does not do: a local run still installs the browsers with `playwright install --with-deps`; a Playwright upgrade must change the image's tag and digest in the same PR, which the contract test enforces for the tag.
