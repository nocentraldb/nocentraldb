# 2026-11-10 · NOC-95 · The owner decides six SDK choices as recommended: storage, the account key, Rust names, error codes, the space id and writing a reference

- Decided by: Carsten, 2026-11-10, on NOC-95
- Why: `OpenOptions::path(dir)` for the database, the member key in the platform keystore, `key_file(path)` for a headless agent without one, and `in_memory()` for tests (RFC 0003 decision 16, RFC 0009 S19); each database draws its own account key once and keeps it next to the member key, and `agent()` marks the member as an agent, until an accounts RFC (NOC-107) links devices (RFC 0003 decision 17, RFC 0009 S20); the Rust names `ObjectId`, `SpaceId`, `ChangeId`, `Object`, `Written` and `page.has_more` next to RFC 0009's Terms (S21); an unknown collection, field or index is `notFound`, a full disk `storageFull`, any other storage failure the new `storageFailed`, a bad query `invalidValue`, an unreadable or invalid lock `modelRefused` (S22, option B); a space id in TypeScript is 32 lowercase hex digits (S23); an app writes a reference as the `{ space, id }` it reads, or `null` (S24). NOC-106 writes them into RFC 0003 and RFC 0009.
- Instead of: the app data directory or memory only (S19 B, C); an account key the app passes, or no spaces before the accounts RFC (S20 B, C); other Rust names (S21 B); every storage failure as `storageFull` (S22 A); another space id form (S23 B); a read object of the target as the written reference (S24 B).
- Topics: rfc-0003, rfc-0009, sdk, keys, names, errors
