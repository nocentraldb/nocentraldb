# 2026-11-11 · NOC-57 · A space of another model parks every sealed change as "another model" at step 6

- Decided by: coding agent (NOC-57), on RFC 0009's "Spaces of another model" ("That space's changes are not folded, nothing is written into it"); the error code `spaceOfAnotherModel` is RFC 0009's
- Why: `db.spaces.get` already refused a space of another model, but each of its sealed changes without its own key 64 folded into the view. The check belongs in core's receive pipeline, the one place every change passes, natively and on wasm32. A new `Checks::space_model_id`, which defaults to `None` and checks nothing, gives the `model.id` of the space's genesis. `SealChecks` reads it again after every control change, so each sealed change costs no extra decryption. At step 6, right after the payload opens, a sealed change of a space whose genesis model differs from `Fold::model_id` is parked as `ParkReason::AnotherModel`, before the format and key-64 checks. Control changes still fold, so the member can name the space's model and the relay's rules hold. The parked changes stay in the log and are counted. A member that later opens the database with a lock of the space's model would fold them again only through a rebuild, which RFC 0005's device check makes impossible across `model.id`s.
- Instead of: refusing the space's changes at the sync layer, which would leave the core folding them for any other caller; dropping the changes, which would lose data and the relay confirmations; a new park reason, when RFC 0009 already names "another model" and the effect is the same.
- What this does not do: a genesis whose sealed `model.id` does not open under the first generation's key gives no model, so the check does not run for that space; its changes fold as before. The test fixtures' simulated spaces now name the tests' lock model by default (`support::space::MODEL`), since a space of another model no longer folds.
