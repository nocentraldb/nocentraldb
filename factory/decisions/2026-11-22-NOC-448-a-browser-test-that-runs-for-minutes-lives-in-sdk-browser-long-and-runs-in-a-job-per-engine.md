# 2026-11-22 · NOC-448 · A TypeScript SDK browser test that runs for minutes lives in scripts/sdk-browser/long/ and runs in a job per engine

- Decided by: coding agent
- Why: the `view` job reached 24 min 13 s of its 30 after NOC-444's eleven-minute idle test and NOC-439's write-cost guard (the Chromium step took 11 min, Firefox 7, WebKit 3, all the builds and other tests together about 7). Those two files move to `scripts/sdk-browser/long/`, which the `view` job's glob `scripts/sdk-browser/*.test.mjs` does not reach, and the job `long` runs them with a matrix over Chromium, Firefox and WebKit, `fail-fast: false`, each job building only the TypeScript SDK (wasm-bindgen and `scripts/sdk-browser/build.mjs`), so the longest, Chromium, takes about 15 minutes and `view` about 10. A later browser test that idles or loops for more than about a minute goes to `long/` too; the moon task `sdk-browser-long` runs the folder locally. `scripts/browser-view-workflow.test.mjs` holds the job's shape and that `view` never runs the folder. Neither job is a required check (the ruleset requires `gates` and `changes`), so no required check changes.
- Instead of: one long job running all three engines one after another (about 20 minutes, near the limit again with the next long test); a job per engine for every browser test, which builds the Rust and wasm parts three times for tests of seconds; raising `timeout-minutes`, which only moves the limit.
