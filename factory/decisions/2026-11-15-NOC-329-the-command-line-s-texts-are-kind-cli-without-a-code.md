# 2026-11-15 · NOC-329 · The command line's texts are entries of kind cli, without a code, and its diff notation stays in code

- Decided by: pm, NOC-329, on the coding agent's proposal
- Why: the `ncdb` command line's texts carry no `ErrorCode`, and some are status lines, not errors, so they are a kind of their own, `cli`, named `cli.<name>`, with no code and with when each shows. `scripts/texts.mjs --write` generates `crates/ncdb/src/texts.rs` from them, a constant per text or a function that fills its placeholders, as for the SDK. They are the usage, every error and status line of `args.rs`, `model.rs` and `schema.rs`, the two messages of the schema script, which `ncdb` passes to the script as arguments, and the build report's sentences. The report's diff notation (`+ collection tasks (3 fields)`, `~`, `-`, `x`, "personal to …") is output format, not prose, and stays in code; the core's refusal lines move in T6, and the system's and the schema's own errors stay values. The gate `repo:texts` reads the command line's code too: a `&str` constant, the script's `fail` given a literal, or any literal with two words in a row is a text written in code, except on a line marked `// notation`; and every `cli` text must be used.
- Instead of: the kind `error` with a made-up code, which RFC 0009's codes do not have; or every literal of the report, the notation's labels included, which would make the gate a list of exceptions.
- Topics: texts, cli, gates
