# 2026-11-12 · NOC-257 · `ncdb-relay --allow-invitation` admits the account an invitation names

- Decided by: Carsten, 2026-11-12, on NOC-239 (A); built in NOC-257 by a coding agent
- Why: the local relay lets a space be created only by a member of an account it was started with, by the account key in hex (`--allow-account`). The public SDK never shows that key: an `Invitation` gives the fingerprint, and its text. So a developer who uses only the public API could not start a relay their app may create spaces on. The relay now reads the account key from an invitation's text (RFC 0003, "Invitation"), at offset 65 of the layout, and admits that account. The text is checked as RFC 0003 has every reader check it: prefix, unpadded base64url with unused bits zero, version, kind, statement byte, account key number and length. A text that fails stops the relay at start with exit code 2, and the message says which check failed but repeats nothing of the text and no key. The relay does not verify the certificate: it admits an account, and each member's connection proves its own key. The reader is a module of the `ncdb-relay` binary, about 40 lines with its own strict base64url decoder: the SDK's reader is crate-internal and the core has none, and pulling in the SDK or adding `data-encoding` to the relay server for 40 lines was not worth a dependency. It keeps to RFC 0003's vectors (`docs/rfc/vectors/0003/`), as the SDK's reader does, so the two cannot drift unseen.
- Instead of: a public `Invitation::account_key()` in the SDK, which would put a key type into an API that so far shows none (NOC-239 B); a relay open to any account on loopback, which teaches developers to run a relay that admits anyone (NOC-239 C); moving the invitation reader into the core for both the SDK and the relay, a refactor of the SDK that the flag does not need.
- Tests: `ncdb-relay-server/tests/allow_invitation.rs` (an invitation's account creates a space; another account does not; the flag combines with `--allow-account` and repeats; every text RFC 0003 refuses stops the relay at start without being repeated); unit tests of the reader against the vectors and RFC 4648's examples.
- Topics: relay, cli, invitation, developer-experience
