# 2026-11-23 · NOC-442 · A person-key entry whose causal past is the last fold's set is added to that fold, and causal pasts are ranges of node numbers

- Decided by: Carsten (option B, 2026-11-23, NOC-442); its form: coding agent (NOC-442)
- Why: step 1 judged each node from a fold of its causal past from scratch, and each node kept its past as a set of change ids, so opening a space with 10,000 persons walked about 50 million nodes and held about 3 GB. `membership::Resolver` now carries one fold of a set without a gap from node to node and call to call (`extend::Running`): a person-key entry whose causal past is exactly that set comes last in step 4's order and changes neither seniority nor an edge between the set's nodes, so it is judged from that fold and added to it as step 5 judges the last change of the order. Every other node is folded from scratch. Causal pasts are ranges of numbers the resolver gives each node after its dependencies, one range per node of a chain. `resolve` stays the definition: `Resolver::from_scratch` folds every past from scratch, and the convergence tests check the resolver against it in every order of arrival. Any change to steps 2 to 5 must keep `Running::extend` equal to them for a person-key entry.
- Instead of: persisting the judgements in the view (option A: an on-disk format change, and the reopen only), or extending the fold by every kind of control change (more of steps 2 to 5 to keep equal, for changes that are few)
