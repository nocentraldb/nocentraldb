# 2026-11-23 · NOC-508 · A pull request that removes, skips or loosens a test passes only with a `Test-change: <reason>` trailer

- Decided by: Carsten (2026-11-23, option A of NOC-508, in the pm session)
- Why: a weakened test was caught only by pm's review, which an agent does and another agent can talk past. Our own check (`scripts/check-test-changes.mjs`) flags, against the pull request's merge base, a removed Rust `#[test]` or TypeScript `it`/`test`, a new `#[ignore]`, `.skip`, `.only` or skip option, a removed `assert*!`, `expect(` or `assert`, and a changed literal in an assertion. A flagged pull request passes only when one of its own commits carries a `Test-change: <reason>` trailer that names the reason in words; pm reads the reason in review, and the daily note lists the pull request. It is deterministic, runs no third-party code in CI, and keeps the reason in the history next to the change. It does not catch everything: a broader matcher, a longer timeout or a weaker fixture still gets through, and review keeps that part.
- Instead of: honest-ci, the third-party action, pinned to a commit SHA (B: a supply-chain and licence check, unclear Rust coverage, and an "approve" step that in a solo repository nobody but the owner's own account could press); CODEOWNERS on the test directories (C: every test change would go to the owner, the bottleneck); or pm's review alone (D). Mutation testing on the touched files is a later step, costlier in CI time.
- Topics: factory, gates, tests
