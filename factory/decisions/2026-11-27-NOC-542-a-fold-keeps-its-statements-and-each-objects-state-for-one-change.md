# 2026-11-27 · NOC-542 · A fold keeps its prepared statements and each object's state for the change it folds, and changes `objects` only through `keep_object`

- Decided by: coding agent (NOC-542); no new crate: pm
- Why: a write of 1,000 objects in Chromium got 8–20 % slower after 0.1.0-beta.2. The fold prepared each SQL statement again for every operation, which took about a third of its time, and since NOC-475 it read the object's row from `objects` again for every field operation, to learn whether the object is a moved trace: 14 statements and 4 reads of `objects` per task of two fields. `SqlFold` now runs every statement through `view::fold_statements::Statements`, which prepares each SQL text once per fold and keeps it until the fold ends. It also remembers the state of each object it read or wrote. That memory is sound only while the `objects` table changes through `SqlFold::keep_object` alone, which a create, delete, move or take-back and a cleared object call. A fold lives for one change, creates and drops no table and runs no savepoint, so nothing it keeps outlives what it read. A later write to `objects` inside a fold goes through `keep_object`, and a later statement of the fold through `Statements`. `tests/view_fold_work.rs` holds a fold to a fixed number of prepared statements and one read of `objects` per object, through the hidden `View::fold_work`; `tests/view_move_one_fold.rs` covers each way an object becomes a trace or stops being one inside one fold.
- Instead of: rusqlite's `prepare_cached`, which needs its `cache` feature and the `hashlink` crate, a supply-chain choice for the owner. It was measured on main at 75 / 101 / 486 / 587 ms for writes of 100 and 1,000 objects into a small and a large space, against 88 / 112 / 580 / 672 ms on beta.2. Another option not taken: a column for the trace in `objects`, an on-disk format change.
- What this does not do: a fold still formats each statement's SQL text for every operation, to find the kept statement; and a write of one object per change, one fold each, gains nothing from statements kept for one fold.
- Topics: core, local-view, performance, browser
