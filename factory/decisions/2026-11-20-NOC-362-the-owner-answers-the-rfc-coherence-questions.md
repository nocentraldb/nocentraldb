# 2026-11-20 · NOC-362 · The owner answers the seven questions of the RFC coherence pass

- Decided by: Carsten, 2026-11-20, on NOC-362 ("Ja zu den Empfehlungen", to each recommendation pm put in brackets)
- Why: the coherence pass (#387 to #389) found seven places where the glossary or a decided RFC said less or other than the code and the decision log, and where only the owner could decide. The answers: (1) a link stays inside its space, and the glossary gets a row for the reference (`nc.ref`), which may point into another space; the RFCs already said so. (2) `ncdb-harness` stays unpublished for 0.1, with its name reserved on crates.io, and is published later; plugin authors do not need it at 0.1. (3) An erasure stays a work order in the design; 0.1's `Db::erase` is an interim call that the work-order RFC will replace. (4) RFC 0003 keeps the notices of moving data between spaces and of invitations, marked as later. (5) A plugin field is Rust only in v1, and RFC 0005's example says so. (6) RFC 0002 states that key 0 is "must understand", the wire-format rule the core already follows (2026-11-08-NOC-14-key-0-is-must-understand.md). (7) RFC 0002 states the exception RFC 0007 already names: a change the relay holds is answered `duplicate` to its own author even after the author left, so a leave whose answer was lost is still confirmed (NOC-276).
- Instead of: (1) links that cross spaces, as the glossary said; (2) publishing `ncdb-harness` with the 0.1 beta; (3) `Db::erase` as the lasting design; (4) dropping the two notices; (5) leaving the TypeScript side of a plugin field unsaid; (6) and (7) leaving the code's rule out of the RFC.
- Topics: rfc, glossary, plugins, erasure, wire-format, relay
