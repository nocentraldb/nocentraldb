# 2026-11-16 · NOC-329 · The TypeScript SDK's texts are entries of kind ts, and the bridge's are the Rust SDK's

- Decided by: pm, NOC-329, on the coding agent's proposal
- Why: T3 brings the TypeScript SDK's and the bridge's developer-facing texts into texts/texts.json, as T1, T2 and T5 did for the Rust SDK and the command line.
  - **The kind `ts`.** The TypeScript SDK's texts are a kind of their own, `ts`, named `ts.<name>`. A `ts` text carries its `code` when the SDK throws it as an nc.Error, and that code must be one RFC 0009's error table lists, as the TypeScript SDK throws a code the Rust SDK has none for (`lockOutOfDate`). It carries no code when the schema throws it as a plain Error, which `ncdb model build` shows. Each has its `when`. A Debug placeholder `{name:?}` is refused.
  - **The generated module.** `scripts/texts.mjs --write` also writes packages/sdk/src/texts.ts: a constant per text, or a function that fills its placeholders in order. The package's entry does not reach it, so the API report does not change. Biome does not format it, as it does not format the generated API report.
  - **The bridge.** Its messages become Rust entries of kind `error`, as T2's are, named `error.bridge<Name>`, and the gate no longer skips src/bridge/. They generate a file of their own, crates/nocentraldb/src/texts/bridge.rs, used as `texts::bridge::NAME`, which keeps error.rs under the repository's 700-line limit for a file.
  - **The gate.** It reads packages/sdk/src, outside texts.ts and the tests. An nc.Error's or an Error's message, or a tab's answer error (`failure`), given a string or a template literal, is a text written in code. Every `ts` text must be used, as `texts.NAME` or `texts.name(`. A value passed on, such as the worker's own error, stays a value, as T2 keeps the system's errors.
- Instead of: one entry for both SDKs under the kinds `error` and `part`. The Rust module would then carry the TypeScript-only texts and the TypeScript module the Rust SDK's 130, and "every text is used" would need both codebases to answer for one entry.
- Topics: texts, sdk-ts, gates
